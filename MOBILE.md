# Mobile

The decision, made 2026-09-08: Bagholder stays local-first on every platform. Nothing leaves the user's device, so there is no server for the apps to lean on, and each app carries the whole model. The native apps are plain native: SwiftUI on iOS, Jetpack Compose on Android, in `ios/` and `android/` of this repository. Each has its own implementation of the model, and the three implementations are kept in agreement by `fixtures/cases`, run through every implementation's tests, so a rule changed in one and not the others fails a PR before it lands.

## What exists

- Branch `ios`: the `ios/` folder of `ios-m1-shell` (PR #15, the working SwiftUI app as of 2026-09-01: Connect, a live Wealthsimple pull, Home tiles, Closed trades with executions) placed on today's master, plus `ios/Bagholder/Model.swift`. The branch's changes outside `ios/` were web-side and are superseded, so they were dropped. It builds on Xcode 26 for the iPhone 17 simulator.
- `ios/Bagholder/Model.swift`: the Swift model, a port of `model.py` function for function (normalize, assignment shares, FIFO with option rolls and the multileg quantity inference, assumed expiries, FX, round trips, positions, cashflow, KPIs, the Cashflow holdings and tiles). The screens draw from it: `WSPull.roundTrips` and `WSPull.openLots` turn the model's trades and lots into the rows Home, Closed trades and Open lots render, and the older matcher that `ios-m1-shell` carried is gone.
- `android/`: a Gradle project with two modules. `model` is a plain Kotlin library that is the same port (`android/model/src/main/kotlin/com/bagholder/model/Model.kt`); `ModelCasesTest` runs `fixtures/cases` through it and passes on all fifteen (`cd android && ./gradlew :model:test`; the test task lists the cases directory as an input so a regenerated case reruns it). `app` is the Jetpack Compose app (`android/app/src/main/kotlin/com/bagholder/app/`): `WSPull.kt` is the Wealthsimple pull ported from the iOS `WSPull.swift` (session from the login cookie, token refresh, the GraphQL calls, the activity mapping, Bank of Canada FX), `Queries.kt` the GraphQL documents generated from the Swift file, `Store.kt` the on-device storage (session in private preferences, the last pull as JSON in the app's files), `Journal.kt` the state and the pull, `MainActivity.kt` the screens: Connect (the Wealthsimple login in a WebView, the session cookie read from the WebView's cookie store), Home (realized P&L, biggest winner and loser by underlying, profit factor, expectancy, win rate, average hold), Closed trades with each trade's executions, Open lots. It does not yet have the NAV chart, the yearly returns against the index, or filters. Build with `cd android && ./gradlew :app:assembleDebug` (JDK 17 or newer, `ANDROID_HOME` or `local.properties` pointing at the SDK, compileSdk 34); the APK lands in `app/build/outputs/apk/debug/`. Verified on 2026-09-08 in the `Medium_Phone_API_35` emulator, headless (`emulator -avd Medium_Phone_API_35 -no-window`), with the app's storage seeded from the fixture cases: every figure on Home, Closed trades, executions and Open lots matched the Python model on the same rows. The login page loads in the WebView; the pull itself has not run against a real account yet.
- `ios/BagholderTests/ModelCasesTests.swift`: the Swift side of the shared cases. It reads `fixtures/cases`, runs each through `BHModel.buildBase`, `kpi` and `cashflowView`, and compares the whole `expect` object field by field. On 2026-09-08 all fifteen cases pass. Run it with `cd ios && xcodebuild test -project Bagholder.xcodeproj -scheme Bagholder -destination 'platform=iOS Simulator,name=iPhone 17' -only-testing:SpikeLoopback/ModelCasesTests` (the test target is named `SpikeLoopback`). The Simulator's test host is an app named Bagholder, so a crash in a test shows up on the Mac as "Bagholder quit unexpectedly"; that is the Simulator, not the desktop app.
- `fixtures/cases` and `test_fixtures.py`: fifteen cases generated from the Python model by `fixtures/make_fixtures.py`: share round trips and open lots, a short option covered, a same-day roll folded into the far contract, a multileg roll that carries the unposted leg, a credit roll up, posted short and long expiries, an assumed expiry, call and put assignments (the derived share leg), crypto with a staking reward, and three Cashflow holdings (declared record, between ex-date and pay day, payments only). `expect` covers trades with their fill labels, KPIs, positions, Cashflow holdings and tiles.

## The plan

1. **iOS first.** Done so far: branch `ios` with the app on master, the Swift model in `Model.swift` feeding the existing screens, and all fifteen cases passing in Python, Swift and Kotlin. Next: the screens the web app has gained since 1 September: Positions, Cashflow with its tiles and Allocation donut, the trade chart, the filter search. Build and run in the Simulator each round (the Simulator can be driven from Claude Code). One rule: a Swift model change comes with the case that proves it, on both sides.
2. **Android**, in `android/`, Kotlin with Jetpack Compose. The model, its fixture test and the app exist (above), the app at the iOS app's starting point (Connect, pull, Home, Closed trades, Open lots). Next: a real pull to confirm the login capture and the sync end to end, then the same screens as iOS gains them. Gradle builds an APK for direct install; the AAB for the Play Store is the same project with one flag.
3. **The Wealthsimple login on a phone** has no Chrome to capture from. Each app does it in its own web view and captures the session cookies from there; the desktop's `_cdp_cookies_from_target` in `bagholder.py` shows which cookies and which fields.
4. **Add cases as rules are touched.** Every model change on any platform comes with a case in `fixtures/cases` if none covers it. The cases are the contract; `SPEC.md` is the meaning.

## Rules that carry over

Everything in `CLAUDE.md` and `SPEC.md`: only what was asked, per-instrument figures in the instrument's currency, aggregates in CAD unlabelled, payout frequency from the fund's record, raw rows never rewritten, nothing synthetic on a chart. A phone screen is a layout of the same figures, not a new definition of them.
